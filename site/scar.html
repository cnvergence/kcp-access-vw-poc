SelfClusterAccessReview API

A single API call that answers: which workspaces does this user have access to?

Endpoint

HTTP endpoint
POST /services/access/apis/access.kcp.io/v1alpha1/selfclusteraccessreviews

Request

Callers authenticate with a bearer token, a client certificate, or via the front-proxy (which presents its requestheader client certificate before its X-Remote-* headers are trusted).

curl examples
# Via the kcp front-proxy
curl -k -X POST   -H "Authorization: Bearer $KCP_TOKEN"   -H "Content-Type: application/json"   -d '{}'   https://root.kcp.example:6443/services/access/apis/access.kcp.io/v1alpha1/selfclusteraccessreviews

# Direct against the virtual workspace (local dev, bearer token)
curl -k -X POST   -H "Authorization: Bearer $TOKEN"   -H "Content-Type: application/json"   -d '{}'   https://localhost:9443/services/access/apis/access.kcp.io/v1alpha1/selfclusteraccessreviews

Response

JSON payload
{
  "kind": "SelfClusterAccessReview",
  "apiVersion": "access.kcp.io/v1alpha1",
  "status": {
    "clusters": [
      {
        "clusterName": "33daicwbox20zsxj",
        "endpoint": "https://root.kcp.example:6443/clusters/33daicwbox20zsxj"
      },
      {
        "clusterName": "workspace1",
        "endpoint": "https://root.kcp.example:6443/clusters/workspace1"
      }
    ]
  }
}

How it works

The RBAC provider watches bindings and their referenced roles across opted-in workspaces. It adds subject-to-cluster mappings only for roles with a resource-read grant. A SCAR request only needs identity resolution plus a graph lookup.

That is why SCAR can answer “where can this user go?” in one shot instead of repeating SelfSubjectAccessReview across every workspace.

Debug endpoint

Graph snapshot
curl -k -H "Authorization: Bearer $TOKEN" https://localhost:9443/debug/graph

Returns the current in-memory graph snapshot so you can inspect which subjects map to which clusters. Served over HTTPS and requires an authenticated user; anonymous requests get 403.
