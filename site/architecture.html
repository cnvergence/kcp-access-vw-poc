System architecture

The ADR 007 flow has two faces: SCAR for fast workspace discovery, and MCP for per-user tool exposure through an AI gateway.

Components

MCP Client

Claude Code, Copilot, or any MCP-capable client that authenticates with Keycloak and speaks MCP over HTTP.

AI Gateway

Envoy receives MCP traffic, enforces OAuth, and forwards the caller's Authorization header to the backend path.

Keycloak

OIDC issuer for user login, dynamic client registration, and access tokens with the aud: kcp audience.

access-vw

A virtual-workspace root apiserver exposing both virtual workspaces (SCAR and MCP) over TLS on :9443.

Permission graph

An in-memory subject-to-cluster index built from watched ClusterRoleBindings and RoleBindings.

kcp cluster

The source of truth for identity validation and workspace RBAC state across bound workspaces.

Two traffic paths

SCAR via front-proxy

The kcp front-proxy authenticates the caller first, injects X-Remote-User and X-Remote-Group, and forwards the SCAR request to access-vw.

MCP via AI Gateway

Envoy forwards the bearer token directly to access-vw, which validates it using its own OIDC authenticator (same issuer/claims configuration as kcp). access-vw scopes the MCP tools to that user's workspaces. This avoids the front-proxy hop for MCP traffic.

ADR target design

The setup implements the ADR 007 target design with two traffic paths: SCAR goes through the kcp front-proxy (AI Gateway → front-proxy → access-vw), while MCP traffic goes directly to access-vw (AI Gateway → access-vw). access-vw validates OIDC tokens itself for MCP requests, using the same issuer/claims configuration as kcp.

Per-workspace calls use impersonation (Impersonate-User / Impersonate-Group headers backed by access-vw's own kcp identity, which holds impersonation RBAC). kcp re-authorizes every impersonated request, and audit logs record both identities.

Permission graph

The graph is populated by the RBAC provider, which watches workspaces that opt in by binding the access.kcp.io APIExport. Every relevant subject — users, groups, and service accounts — is mapped to the logical clusters it can reach.

Why this design? The expensive work happens continuously in the background. SCAR and MCP requests become cheap lookups against already-indexed RBAC state.
