Local setup guide

Deploy the full stack into a local Kind cluster.

Prerequisites

Core tools

Kind, kubectl, Helm, jq, Docker, and Go 1.26+ are required to build and deploy the stack.

Local TLS helpers

mkcert is required for generating host-trusted Keycloak TLS certificates so MCP clients can complete the OAuth flow over HTTPS.

One command setup

Bootstrap
make kind-setup

This delegates to make -C hack/kind setup and installs the full ADR 007 stack in order.

What gets deployed

ComponentPurpose
kcpWorkspace control plane, OIDC validation, front-proxy, and logical cluster endpoints
KeycloakOIDC provider with test users, dynamic client registration, and the aud: kcp audience mapping
Envoy AI GatewayMCP-aware ingress path with HTTPS, OAuth integration, and token forwarding
access-vwSCAR + MCP backend backed by the in-memory permission graph

Connecting an MCP client

Copilot CLI / Claude Code
# The Kind setup deploys an AI Gateway with OAuth.
# Point your MCP client at the gateway URL:
{
  "mcpServers": {
    "kcp": {
      "type": "http",
      "url": "http://mcp.kcp.example:8080/mcp"
    }
  }
}

# The gateway handles OAuth (via Keycloak), validates the token,
# and forwards it to access-vw which scopes tools to your workspaces.

# Alternative: generate a scoped kubeconfig for use with upstream MCP server
make mcp-demo

The AI Gateway discovers Keycloak via protected resource metadata, so MCP clients automatically authenticate via OAuth. Copilot CLI and Claude Code both support the http transport type.

Testing

Useful commands
make -C hack/kind scar USER=alice
make -C hack/kind get-token USER=alice

# from inside hack/kind/:
make scar USER=alice
make get-token USER=alice

Use scar to validate the workspace list for a user, and get-token to inspect or reuse a real OIDC token.

Teardown

Cleanup
make kind-teardown
