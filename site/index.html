Permission-aware workspace discovery for kcp

kcp-access-vw answers “which workspaces does this user have access to?” with a single API call, then exposes the result as MCP tools for AI assistants.

The short version

  1. 1
    RBAC indexing. The server watches ClusterRoleBindings and RoleBindings across all kcp workspaces and translates them into an in-memory permission graph.
  2. 2
    Identity resolution. The apiserver authentication layer resolves the caller — front-proxy requestheader mTLS, bearer token (TokenReview against kcp), or client certificate. The resolved identity is checked against the permission graph.
  3. 3
    Scoped tool exposure. Only the workspaces that user can access are exposed as MCP tools. An AI assistant sees exactly what that user is authorized to — no more, no less.

Why it matters

One call, many workspaces

SCAR replaces a fan-out of per-workspace auth checks with one permission-aware response.

Native kcp semantics

The indexer understands kcp workspaces, APIBindings, and logical cluster endpoints.

Agent-safe scoping

MCP sessions inherit the caller's access boundary automatically, without custom policy glue.
